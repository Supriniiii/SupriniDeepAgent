# Documentation Engineering Standards

1. **Implementation Accuracy**: Documentation must be generated from or validated against actual implementation artifacts. No documentation may describe behavior that differs from the current implementation state.

2. **Completeness Coverage**: Every public interface, configuration option, deployment step, and architecture decision must be documented. Documentation completeness is measured against a defined checklist and gaps block completion.

3. **Practical Examples**: All API documentation and configuration references must include working examples that can be executed by the reader. Examples must be tested and verified as part of the documentation generation process.

4. **Consistent Structure**: All documentation must follow established templates and style guides. Section ordering, heading levels, terminology, and formatting must be consistent across the entire documentation package.

5. **Audience Awareness**: Documentation must be written for its intended audience. Operator guides focus on deployment and operations. Developer guides focus on extension and contribution. Architecture docs focus on decisions and trade-offs. Each audience gets appropriate depth and context.
