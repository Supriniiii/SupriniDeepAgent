# Workflow Purpose

Coordinate software engineering activities from request intake through code generation, validation, and delivery.

---

# Workflow Stages

## Stage 1 — Request Intake

**Purpose:** Understand the developer request and identify the engineering task.

**Outputs:** Normalized request, task classification, complexity assessment.

---

## Stage 2 — Repository Discovery

**Purpose:** Analyze project structure, conventions, dependencies, and existing code.

**Responsible Component:** Repository Analyzer

**Outputs:** Project context, conventions, dependency map, relevant files.

---

## Stage 3 — Planning

**Purpose:** Decompose the engineering task into actionable coding steps.

**Responsible Component:** Planner

**Outputs:** Execution plan, file list, modification strategy, test plan.

---

## Stage 4 — Code Execution

**Purpose:** Generate, modify, or refactor code according to the plan.

**Responsible Component:** Executor + Code Generator

**Outputs:** Generated/modified source files, documentation updates.

---

## Stage 5 — Test Generation

**Purpose:** Create tests that validate the generated code.

**Responsible Component:** Test Generator

**Outputs:** Unit tests, integration tests, test execution results.

---

## Stage 6 — Reflection

**Purpose:** Review generated code for quality, completeness, and adherence to conventions.

**Responsible Component:** Reflection

**Outputs:** Quality observations, improvement recommendations.

---

## Stage 7 — Verification

**Purpose:** Verify that generated code satisfies requirements and passes validation.

**Responsible Component:** Verifier

**Outputs:** Verification report, pass/fail status.

---

## Stage 8 — Evaluation

**Purpose:** Assess overall code quality, maintainability, and engineering effectiveness.

**Responsible Component:** Evaluator

**Outputs:** Quality score, engineering metrics.

---

## Stage 9 — Delivery

**Purpose:** Present validated results to the developer.

**Outputs:** Final code, documentation, test results, engineering summary.

---

## Stage 10 — Memory Update

**Purpose:** Persist learned conventions, decisions, and project context.

**Responsible Component:** Memory Manager

**Outputs:** Updated project memory, session archive.

# Decision Points

| Decision | Rule | Action |
|----------|------|--------|
| Code quality insufficient | Reflection identifies issues | Return to Code Execution |
| Tests fail | Verification detects failure | Return to Code Execution |
| Missing context | Repository discovery incomplete | Expand discovery scope |
