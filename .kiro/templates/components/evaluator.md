# Purpose

The Evaluator measures execution quality using quantitative metrics. Unlike the Verifier (which produces pass/fail verdicts), the Evaluator produces numerical scores across multiple quality dimensions, enabling comparison between different outputs, tracking quality trends over time, and identifying areas where execution quality is degrading or improving. It provides the measurement foundation for continuous improvement.

---

# Responsibilities

- Define and apply quality metrics to execution outputs
- Compute scores across multiple quality dimensions (correctness, efficiency, completeness, maintainability)
- Aggregate dimensional scores into an overall quality score
- Compare current scores against historical baselines
- Detect quality trends (improvement, degradation, stability)
- Produce quality reports with dimensional breakdowns
- Feed quality data to the reflection and improvement components
- Support configurable scoring models and weightings

---

# Scope

This component covers quantitative quality measurement. It produces numerical scores and trend data. It does NOT make pass/fail decisions (that is the Verifier's job), generate improvement recommendations (that is the Improvement component's job), or reflect on execution patterns (that is the Reflection Engine's job). It answers: "How good is this output, measured on a scale?"

# State Management

The Evaluator maintains a lightweight score history for trend detection. Current evaluation state is ephemeral per invocation. Historical scores are retrieved from long-term memory for baseline comparison. After evaluation, scores are emitted and stored externally — the Evaluator itself does not own score persistence.

---

# Error Handling

- Missing metrics: Score available dimensions, flag gaps in the quality report
- Scoring model not found: Fail evaluation with "no model" error
- Historical data unavailable: Skip trend analysis, produce scores without comparison
- Score calculation error: Flag specific dimension as unscored, produce partial report
- Model version mismatch: Apply available model, note version discrepancy in report

# Validation Requirements

- All dimensions defined in the scoring model must be evaluated or explicitly marked as not applicable
- Scores must be normalized to the configured scale
- Overall score must be a weighted aggregate (not an average) of dimensional scores
- Trend detection must require a minimum number of historical data points
- Quality report must include the scoring model version used
