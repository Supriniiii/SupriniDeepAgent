# Purpose

The Output Validator verifies that generated outputs conform to their expected format, structure, and completeness requirements. It checks that all required fields are present, data types are correct, structures follow defined schemas, and no mandatory sections are missing. It provides the structural layer of verification — ensuring the output is well-formed before deeper semantic checks are applied.

---

# Responsibilities

- Validate output structure against defined schemas
- Check for required fields, sections, and elements
- Verify data types and value constraints
- Validate file formats and encoding
- Check completeness — all expected artifacts are present
- Verify naming conventions in generated artifacts
- Validate cross-file references and imports
- Report structural violations with exact location and expected values

---

# Scope

This component covers structural and format validation. It ensures outputs are well-formed and complete in terms of structure. It does NOT assess semantic correctness (that is the Verifier's job), check for contradictions (that is the Consistency Verifier's job), or verify policy compliance (that is the Policy Verifier's job). It answers: "Is this output structurally valid and complete?"

# State Management

The Output Validator is completely stateless. Each validation request is independent and self-contained. Schemas and rules are retrieved fresh from their respective stores on each invocation. No state is maintained between validation calls.

---

# Error Handling

- Schema not found: Reject validation with "cannot validate" status
- Unparseable output: Report as critical structural error at the top level
- Partial schema match: Validate available sections, flag missing schema coverage
- Encoding detection failure: Attempt multiple encodings, report detected encoding
- Excessive errors: Truncate at configured maximum, flag as "additional errors not shown"

# Validation Requirements

- Schema validation must cover all defined fields in the schema
- Required field checks must report each missing field individually
- Type violations must include expected type and actual value type
- Format validation must verify both syntax and encoding
- Completeness check must address every item in the provided checklist
