# Purpose

The Policy Verifier checks generated outputs for compliance with engineering policies, organizational standards, security requirements, and regulatory constraints. It ensures outputs adhere to rules that transcend individual project requirements — policies that apply universally regardless of the specific task. It is the compliance gate that catches policy violations before delivery.

---

# Responsibilities

- Retrieve applicable policies based on output type and domain
- Verify security policy compliance (no hardcoded secrets, least privilege applied)
- Check coding standards adherence (naming, structure, documentation)
- Verify architectural policy compliance (separation of concerns, modularity)
- Check licensing and dependency policies
- Verify observability requirements (logging, metrics, tracing present)
- Detect and report policy violations with severity and remediation guidance
- Support policy waivers for justified exceptions

---

# Scope

This component covers verification against organizational and engineering policies. It checks universal rules that apply regardless of specific requirements. It does NOT verify against project-specific requirements (that is the Verifier's job), check internal consistency (that is the Consistency Verifier's job), or validate output format (that is the Output Validator's job). It answers: "Does this output comply with our policies?"

# State Management

The Policy Verifier is stateless. Policies are retrieved fresh from the policy store on each verification to ensure current versions are applied. No verification state is maintained between checks. Waiver state is owned by the orchestrator and passed in per request.

---

# Error Handling

- Policy store unavailable: Fail verification (cannot verify without policies)
- Unknown policy version: Apply latest available, flag version mismatch
- Secret scanner timeout: Flag as unverified security check, do not pass
- Waiver referenced but not found: Treat as no waiver, apply full policy
- Policy conflict (two policies disagree): Apply stricter interpretation, report conflict

# Validation Requirements

- All applicable policies must be checked (no silent omissions)
- Critical security violations must always block regardless of configuration
- Each violation must reference the specific policy rule violated
- Waivers must only suppress violations for the exact rule specified
- Compliance score must account for violation severity weighting
