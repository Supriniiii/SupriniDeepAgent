# Purpose

The Quality Evaluator assesses generated outputs against engineering quality standards specific to the Deep Agent Engineering Platform. It evaluates architecture quality, security posture, testing adequacy, documentation completeness, deployment readiness, and performance characteristics. It produces a production-readiness assessment that determines whether outputs meet the bar for delivery.

---

# Responsibilities

- Apply engineering quality standards to generated outputs
- Evaluate architecture quality (modularity, separation of concerns, patterns)
- Assess security posture (secret handling, authentication, authorization)
- Measure testing adequacy (coverage, test types, edge cases)
- Check documentation completeness (API docs, README, ADRs)
- Verify deployment readiness (containerization, configuration, health checks)
- Assess performance characteristics (resource usage, scalability indicators)
- Produce a weighted quality score with production-readiness verdict
- Identify quality gaps and recommend remediation priorities

---

# Scope

This component covers assessment against engineering quality standards. It applies the platform's quality framework (architecture 20%, security 20%, testing 20%, documentation 15%, deployment 15%, performance 10%) to produce a production-readiness determination. It does NOT perform generic metric evaluation (that is the Evaluator's job), verify requirements (that is the Verifier's job), or generate improvements (that is the Improvement component's job).

# State Management

The Quality Evaluator is stateless across assessments. Each assessment is independent and produces its own scores. Quality standards are retrieved fresh from the policy store. The evaluator does not track historical quality scores — that is the responsibility of the general Evaluator component which handles trend analysis.

---

# Error Handling

- Quality standards unavailable: Fail assessment (cannot evaluate without standards)
- Architecture analyzer unavailable: Apply heuristic-based architecture scoring, flag reduced confidence
- Security scanner unavailable: Perform manual security checklist, flag as partial assessment
- Test coverage data missing: Score based on test presence/absence rather than coverage percentage
- Dimension score below minimum: Mark dimension as failed, block production readiness
- Waiver requested for failed dimension: Apply if allowed, note in assessment

# Validation Requirements

- All six quality dimensions must be scored (or explicitly waived with justification)
- No single dimension below its minimum score can result in a production-ready verdict
- Weighted overall score must match the sum of (dimension_score × weight) for all dimensions
- Quality gaps must be ordered by impact (largest gap first)
- Assessment must reference the specific quality standards version applied
