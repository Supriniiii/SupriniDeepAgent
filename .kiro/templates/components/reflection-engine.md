# Purpose

The Reflection Engine analyzes completed execution traces to identify what went well, what failed, what was inefficient, and what can be improved. It examines execution patterns, compares actual outcomes against expected outcomes, and synthesizes insights that feed into learning and improvement cycles. It provides the self-awareness mechanism that enables the agent system to evolve over time.

---

# Responsibilities

- Receive execution traces and outcome data from completed workflows
- Analyze execution efficiency (time, resources, steps taken)
- Identify failure patterns and their root causes
- Compare actual outcomes against planned expectations
- Detect recurring inefficiencies and anti-patterns
- Generate structured reflection reports with actionable insights
- Feed insights to the learning and improvement components
- Track reflection history to identify trends over time

---

# Scope

This component covers post-execution analysis and insight generation. It examines what happened during execution and why. It does NOT execute tasks, make real-time decisions during execution, or directly modify future plans. Its outputs inform the Learning and Improvement components, which in turn influence future planning. It operates after execution is complete.

# State Management

The Reflection Engine does not maintain persistent internal state. Each reflection cycle operates on the provided execution trace and optional historical data. Reflection results are emitted to consumers and stored in long-term memory by the Learning component. The engine may cache intermediate analysis results during a single reflection cycle, but this is discarded upon completion.

---

# Error Handling

- Incomplete execution trace: Perform partial analysis, flag gaps in the reflection report
- Missing expected outcomes: Compare against general quality heuristics instead
- Pattern detection failure: Proceed without trend analysis, note limitation in report
- Analysis timeout: Emit partial reflection with incomplete flag
- Historical data unavailable: Perform isolated analysis without trend context

# Validation Requirements

- Reflection report must reference the specific execution trace analyzed
- Each insight must have a confidence score and supporting evidence
- Failure analysis must include at least one probable cause per failure
- Insights must be actionable (not merely observational)
- Report must distinguish between one-time events and recurring patterns
