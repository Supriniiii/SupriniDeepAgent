# Purpose

The Strategy Planner selects the optimal execution strategy based on the current objective, available resources, constraints, and historical performance data. It evaluates multiple candidate strategies, scores them against criteria such as reliability, speed, cost, and quality, then recommends the best-fit strategy for downstream planning and execution components.

---

# Responsibilities

- Analyze the objective to determine applicable strategy categories
- Generate candidate execution strategies based on known patterns
- Evaluate each candidate against weighted selection criteria
- Incorporate historical performance data into strategy scoring
- Select the optimal strategy and produce a strategy decision record
- Provide fallback strategy recommendations in case the primary fails
- Adapt strategy selection based on runtime feedback and changing constraints
- Communicate strategy rationale for audit and learning purposes

---

# Scope

This component covers strategy selection and recommendation. It determines HOW an objective should be pursued at a strategic level (e.g., iterative vs. batch, parallel vs. sequential, depth-first vs. breadth-first). It does NOT decompose tasks into steps (that is the Planner's job) or execute any strategy. It operates between objective reception and plan generation.

# State Management

The Strategy Planner is stateless across invocations. Each strategy selection is independent and self-contained. Historical performance data is read from external memory stores rather than maintained internally. The only transient state is the candidate evaluation context during a single selection cycle.

---

# Error Handling

- No viable strategy found: Escalate to orchestrator with explanation of why all candidates failed
- Insufficient historical data: Proceed with default scoring weights and flag low confidence
- Conflicting constraints: Report constraint conflict and request resolution
- Strategy registry unavailable: Fall back to built-in default strategies
- Scoring timeout: Return highest-scored candidate evaluated so far

# Validation Requirements

- Selected strategy must satisfy all hard constraints
- At least one fallback strategy must be identified
- Strategy rationale must reference specific scoring criteria
- Confidence score must exceed minimum threshold for autonomous selection
- Strategy must be compatible with available executor capabilities
