# Purpose

The Task Executor handles the execution of individual atomic tasks. It receives a single well-defined task with clear inputs, expected outputs, and completion criteria, then executes it using the appropriate tools and resources. It is the lowest-level execution unit that performs actual work, reporting results back to the parent executor upon completion.

---

# Responsibilities

- Receive a single atomic task with defined contract
- Validate task inputs before execution begins
- Select and invoke the appropriate tool or capability
- Process tool outputs and transform into expected task output format
- Validate task outputs against completion criteria
- Handle task-level retries for transient failures
- Report task completion status with result artifacts
- Clean up temporary resources after task completion

---

# Scope

This component covers the execution of a single atomic task from start to finish. It handles tool selection for the specific task, input/output transformation, and task-level error recovery. It does NOT manage multiple tasks, coordinate workflows, or make planning decisions. It is the leaf-level executor in the execution hierarchy.

# State Management

The Task Executor maintains minimal state scoped to the current task execution: task status (pending, running, completed, failed), retry count, and intermediate tool results. State is not persisted beyond the task lifecycle. Upon completion or failure, all transient state is discarded after results are reported upstream.

---

# Error Handling

- Tool invocation failure: Retry with backoff up to configured maximum
- Input validation failure: Reject task immediately with validation error details
- Output validation failure: Retry execution; if persistent, report as task failure
- Timeout: Cancel active tool call, report timeout failure
- Tool not found: Report binding error to parent executor
- Unexpected tool output: Attempt transformation; if impossible, report format error

# Validation Requirements

- Task inputs must satisfy the task contract schema before execution begins
- Tool binding must resolve to exactly one available tool
- Task output must satisfy all completion criteria
- Execution must complete within the configured timeout
- All temporary resources must be cleaned up after execution
