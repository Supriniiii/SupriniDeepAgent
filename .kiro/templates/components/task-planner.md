# Purpose

The Task Planner is a specialized planning component that breaks high-level tasks into ordered subtasks. Unlike the general Planner which handles broad objectives, the Task Planner focuses on granular task decomposition, producing atomic subtasks that can be directly assigned to task executors. It ensures each subtask is self-contained, testable, and has clear completion criteria.

---

# Responsibilities

- Receive parent tasks from the planner or orchestrator
- Decompose tasks into atomic, executable subtasks
- Define clear inputs, outputs, and completion criteria for each subtask
- Establish subtask ordering and parallelization opportunities
- Estimate duration and complexity for each subtask
- Assign subtask types for executor routing
- Detect and flag subtasks that require human approval
- Produce subtask manifests consumable by task executors

---

# Scope

This component covers the decomposition of tasks into subtasks. It handles subtask definition, ordering, and readiness validation. It does NOT execute subtasks, manage task lifecycle during execution, or handle cross-workflow coordination. It operates at the task level, not the objective or strategy level.

# State Management

The Task Planner holds transient state for the current decomposition session, including the parent task being broken down, intermediate subtask candidates, and the dependency graph under construction. State is discarded after the subtask manifest is emitted. For iterative refinement, prior results are passed back in as input.

---

# Error Handling

- Undecomposable tasks: Return to orchestrator with flag indicating task is already atomic
- Circular subtask dependencies: Detect and report as decomposition error
- Missing executor capabilities: Flag subtasks that cannot be routed and suggest alternatives
- Exceeded depth limit: Halt decomposition and emit partial result with warning
- Invalid completion criteria: Request clarification from upstream

# Validation Requirements

- Each subtask must have defined inputs and expected outputs
- Subtask dependency graph must be acyclic
- Every subtask must map to at least one available executor capability
- Completion criteria must be verifiable
- No subtask should exceed the configured complexity threshold
