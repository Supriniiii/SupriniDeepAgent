# Purpose

The Verifier is the primary verification component that validates outputs against their defined requirements, acceptance criteria, and quality standards. It determines whether generated artifacts satisfy the conditions specified by the planner and the user's original request. It serves as the quality gate between execution and delivery, ensuring outputs are correct and complete.

---

# Responsibilities

- Receive outputs along with their corresponding requirements and acceptance criteria
- Verify functional correctness against defined expectations
- Verify completeness — all required elements are present
- Verify format and structural compliance
- Aggregate verification results from sub-verifiers (consistency, policy, output)
- Produce a verification verdict (pass, fail, conditional pass)
- Generate detailed verification reports with specific pass/fail items
- Trigger re-execution or correction when verification fails

---

# Scope

This component covers verification of outputs against requirements. It coordinates sub-verifiers and produces an aggregate verification verdict. It does NOT execute tasks, generate improvements, or measure quality metrics beyond pass/fail. Quantitative quality measurement is the Evaluator's job. The Verifier provides a binary gate: does the output satisfy requirements or not.

# State Management

The Verifier is stateless across verification cycles. Each verification operates independently on the provided output and requirements. Verification results are emitted to consumers and not retained internally. If iterative verification is needed (output revised and re-verified), it is submitted as a new verification request.

---

# Error Handling

- Missing requirements: Reject verification, return "cannot verify" with reason
- Sub-verifier timeout: Proceed with available results, flag incomplete verification
- Sub-verifier failure: Exclude from aggregation, note in report, apply conservative verdict
- Unverifiable criteria: Mark as "not verified" rather than pass or fail
- Contradictory sub-verifier results: Apply strictest result, note conflict

# Validation Requirements

- Every acceptance criterion must be addressed in the verification report
- Verdict must be justified by specific check results
- Failure items must include actionable details for correction
- Verification must not silently skip any requirement
- Conditional passes must list outstanding conditions
