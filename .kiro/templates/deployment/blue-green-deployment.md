# Purpose

Defines a blue-green deployment strategy that maintains two identical production environments (blue and green), enabling zero-downtime releases by deploying to the inactive environment, verifying health, and instantly switching traffic. This provides immediate rollback capability by routing traffic back to the previous environment.

# Deployment Procedure

```text
1. Identify inactive environment (opposite of current active)
2. Deploy new version to inactive environment
3. Wait for all pods/instances to reach healthy state
4. Run full verification suite against inactive environment
5. Warm up inactive environment (pre-load caches, connection pools)
6. Execute traffic switch (DNS update, LB target swap, or service mesh)
7. Monitor error rate and latency during switch stabilization
8. Verify new active environment serves all traffic correctly
9. Keep old environment running for immediate rollback capability
10. After stabilization window, scale down old environment (optional)
```

---

# Validation

- Inactive environment is fully deployed and passing health checks
- Verification suite passes against new deployment before switch
- Traffic switch completes within configured timeout
- Zero requests are dropped during the traffic switch
- Old environment remains healthy and ready for instant rollback
