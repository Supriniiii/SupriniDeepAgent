# Purpose

Defines a canary deployment strategy that progressively routes increasing percentages of production traffic to a new version while continuously monitoring error rates, latency, and business metrics. If metrics degrade beyond thresholds at any stage, traffic is automatically rolled back to the stable version.

# Deployment Procedure

```text
1. Deploy canary version alongside stable with minimal replicas
2. Route {{stage_1_percent}}% of traffic to canary pods
3. Run analysis for {{stage_1_duration}}: compare canary vs stable metrics
4. If metrics pass gate: increase to {{stage_2_percent}}% traffic
5. Run analysis for {{stage_2_duration}}: validate no degradation
6. If metrics pass gate: increase to {{stage_3_percent}}% traffic
7. Run analysis for {{stage_3_duration}}: final validation before full rollout
8. If all gates pass: promote canary to 100% (becomes new stable)
9. Scale down old stable version
10. If ANY gate fails: immediately route 100% back to stable, abort canary
```

---

# Validation

- Canary receives configured percentage of traffic (verified via metrics)
- Error rate on canary stays below threshold compared to stable baseline
- Latency p99 on canary does not exceed stable by more than tolerance
- Business metrics (conversion, success rate) are not adversely affected
- Automatic rollback triggers within one analysis interval of threshold breach
