# Purpose

Defines comprehensive health check configurations for Deep Agent services, covering liveness probes (is the process alive), readiness probes (can it serve traffic), and startup probes (has it finished initializing). This template specifies probe types, endpoints, thresholds, and integration with orchestrators for automated remediation.

# Deployment Procedure

```text
1. Implement liveness endpoint (lightweight, no dependency checks)
2. Implement readiness endpoint (confirms ability to serve traffic)
3. Implement startup probe endpoint (confirms initialization complete)
4. Implement deep health endpoint (checks all downstream dependencies)
5. Configure Kubernetes probe settings with appropriate thresholds
6. Set startup probe failure threshold high enough for slow-starting apps
7. Ensure liveness probe never depends on external services
8. Configure readiness probe to reflect actual traffic-serving capacity
9. Validate probe behavior under failure conditions (kill database, overload)
10. Monitor restart counts to detect liveness probe instability
```

---

# Validation

- Liveness probe returns 200 when application process is healthy
- Readiness probe returns 503 when dependencies are unavailable
- Startup probe allows sufficient time for application initialization
- Failed liveness triggers container restart (verify restart count increments)
- Failed readiness removes pod from Service endpoints (verify no traffic)
