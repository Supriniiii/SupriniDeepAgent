# Purpose

Defines Kubernetes Ingress resources that expose HTTP/HTTPS routes from outside the cluster to internal services. This template configures path-based and host-based routing, TLS termination, rate limiting, authentication, and integration with ingress controllers like NGINX, Traefik, or cloud-native ALB controllers.

# Deployment Procedure

```text
1. Verify ingress controller ({{ingress_controller}}) is deployed and healthy
2. Create TLS secret or configure cert-manager Certificate resource
3. Validate DNS record points to ingress controller external IP
4. Apply Ingress resource with routing rules and annotations
5. Verify Ingress gets assigned an ADDRESS (external IP or hostname)
6. Test HTTP-to-HTTPS redirect for all configured hosts
7. Validate path-based routing reaches correct backend services
8. Confirm TLS certificate is valid and served correctly
9. Test rate limiting and CORS headers in responses
```

---

# Validation

- Ingress resource shows assigned ADDRESS within 60 seconds
- HTTPS requests to {{ingress_host}} return valid TLS certificate
- Path-based routing delivers traffic to correct backend services
- HTTP requests receive 301 redirect to HTTPS
- Rate limiting returns 429 when threshold is exceeded
