# Purpose

Defines Kubernetes Secret resources for managing sensitive data such as passwords, API keys, TLS certificates, and service credentials. This template specifies encryption at rest, RBAC-restricted access, secret rotation strategies, and integration with external secret management systems.

# Deployment Procedure

```text
1. Generate or retrieve secret values from external secret store
2. Encode values as base64 (or use stringData for plaintext input)
3. Apply RBAC policies restricting secret access to required service accounts
4. Apply Secret resource with appropriate type (Opaque, TLS, docker-registry)
5. Configure encryption at rest via EncryptionConfiguration
6. Mount secret in pod spec as volume or inject as environment variable
7. Verify pod can read secret values at expected mount path
8. Configure external secrets operator for automatic sync (if enabled)
9. Set up rotation schedule and alerting for expiration
```

---

# Validation

- Secret is created and accessible only by authorized service accounts
- Pod mounts secret with read-only permissions (0400)
- Secret values are encrypted at rest in etcd
- RBAC denies unauthorized access (verify with kubectl auth can-i)
- Rotation triggers pod restart or re-mount within configured interval
