# Purpose

Defines an advanced multi-stage Docker build pattern that separates dependency installation, compilation, testing, and production packaging into discrete build stages. This maximizes layer caching efficiency, reduces final image size, and ensures build-time tools and test dependencies never reach the production image.

# Deployment Procedure

```text
1. Configure BuildKit with cache backend (registry or local)
2. Stage 1 (base): Set up system packages and create non-root user
3. Stage 2 (dependencies): Copy lockfiles first, install deps (maximizes cache hits)
4. Stage 3 (test): Copy source, run linter, execute test suite
5. Stage 4 (build): Compile/bundle production artifacts with tree-shaking
6. Stage 5 (production): COPY --from=build only runtime artifacts into clean base
7. Set file permissions, non-root user, and HEALTHCHECK instruction
8. Tag image with version, commit SHA, and build timestamp labels
9. Run container structure tests to validate image contents
10. Push multi-arch manifest to container registry
```

---

# Validation

- Each stage builds independently when targeted with --target flag
- Dependency stage cache is reused when only source code changes
- Test stage fails the build if any test or lint check fails
- Production image contains zero build tools, test deps, or source maps
- Image size reduction compared to single-stage build exceeds 60%
