# Purpose

The Cloud Harness provides a managed cloud deployment environment for Deep Agents leveraging cloud-provider-specific deployment services, CI/CD pipelines, and infrastructure automation. It manages cloud resource lifecycle, deployment pipelines, environment promotion, blue-green and canary release strategies, and cloud-native observability to enable reliable, automated agent deployments across development, staging, and production environments.

---

# Runtime Overview

This harness operates on cloud deployment platforms (AWS ECS/Lambda, Azure Container Apps, GCP Cloud Run) with integrated CI/CD pipelines, infrastructure-as-code provisioning, and progressive delivery controls. It provides environment management (dev/staging/prod), deployment approval gates, automated rollback on health check failures, and cloud-native logging and monitoring integration through provider-specific observability services.

# Error Handling

The Cloud Harness monitors deployment health through cloud-native health endpoints and automatically rolls back failed deployments using the provider's built-in rollback mechanisms. Canary deployments that exceed error rate thresholds trigger automatic traffic shifting back to the stable version. Infrastructure provisioning failures are surfaced with cloud-provider-specific diagnostic codes and remediation guidance including IAM permission requirements.

# Validation Requirements

- Infrastructure-as-code changes must pass plan/dry-run validation before apply in any environment
- Deployment pipelines must include automated smoke tests that gate promotion between environments
- Canary metrics must be evaluated against defined SLO thresholds before traffic percentage increases
- Cloud IAM roles must follow least-privilege with documented permission boundaries per service
- Rollback procedures must be tested and verified as functional before enabling production deployments
