# Purpose

The Cluster Harness provides a tightly-coupled multi-node execution environment for Deep Agent workloads that require coordinated resource pooling, shared-nothing architecture, and automatic load balancing across a homogeneous set of compute nodes. It manages cluster membership, shard assignment, rebalancing, and coordinated failover to deliver high-availability agent execution at scale.

---

# Runtime Overview

This harness operates a cluster manager that treats multiple nodes as a single logical execution unit. It handles cluster formation through seed-node bootstrapping, maintains consistent hash rings for shard distribution, performs automatic rebalancing when nodes join or leave, and provides cluster-wide service discovery. The runtime supports rolling upgrades and canary deployments without service interruption.

# Error Handling

The Cluster Harness detects node failures through gossip-based failure detection and automatically redistributes shards to healthy nodes within the rebalancing timeout. During rebalancing, affected requests are queued or rerouted to replica shards to maintain availability. Cluster-wide failures (loss of quorum) trigger a controlled freeze that preserves state and prevents split-brain writes until manual intervention restores cluster health.

# Validation Requirements

- Cluster must achieve quorum (majority of nodes online) before accepting work assignments
- Shard rebalancing must complete without data loss and within the configured rebalancing timeout
- Rolling upgrades must maintain cluster availability throughout the upgrade window
- Node decommission must drain all assigned shards to other nodes before removal from the ring
- Cluster membership changes must propagate to all nodes within the gossip convergence window
