# Purpose

The Coding Harness provides a software engineering execution environment optimized for Deep Agents that perform code generation, refactoring, review, and repository management. It integrates with IDE services, build systems, version control, static analysis tools, and test runners to enable agents that understand and manipulate codebases with full contextual awareness.

---

# Runtime Overview

This harness wraps a code-aware runtime with access to language servers, AST parsers, repository indexing, file system watchers, and build pipeline triggers. It manages workspace contexts, tracks file modifications, validates generated code against linters and compilers, and orchestrates multi-file changes as atomic transactions that can be rolled back on failure.

# Error Handling

The Coding Harness treats compilation errors, lint violations, and test failures as structured feedback that is routed back to the agent for self-correction before surfacing to the user. Syntax errors trigger immediate rollback of the affected file changes to maintain repository integrity. Build system timeouts and dependency resolution failures are isolated and reported with actionable diagnostics including the relevant compiler output and dependency graph.

# Validation Requirements

- Generated code must pass all configured linter rules and compile without errors before commit
- Multi-file changes must be applied atomically with rollback capability on partial failure
- Repository state must remain consistent (no dangling imports, broken references) after every operation
- Build pipeline must execute successfully before any generated code is marked as complete
- Code changes must not introduce regressions as verified by the existing test suite
