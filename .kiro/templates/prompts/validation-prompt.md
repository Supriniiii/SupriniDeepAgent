# Purpose

This prompt instructs the agent to validate that inputs, configurations, and data conform to their expected schemas, formats, and value constraints before they are processed. It acts as a gatekeeper that prevents malformed, incomplete, or out-of-range data from entering the execution pipeline, catching problems early and providing clear diagnostic messages.

# Objectives

- Check all required fields are present and non-null
- Validate data types match the expected schema definitions
- Verify values fall within defined ranges and constraint boundaries
- Detect format violations (dates, emails, identifiers, enums)
- Aggregate all validation errors rather than stopping at the first
- Produce human-readable error messages that guide correction

# Constraints

- Must validate exhaustively, reporting all errors not just the first encountered
- Must not silently coerce invalid data into valid formats
- Must distinguish between required field violations and optional field warnings
- Must validate nested structures recursively to full depth
- Must not allow data to pass validation if any required constraint fails
- Must provide the exact field path for each validation error

# Validation Criteria

- All schema-defined fields are checked including nested structures
- Error messages include field path, expected format, and actual value
- No valid data is incorrectly rejected (no false positives)
- No invalid data passes validation (no false negatives)
- Validation is deterministic and produces identical results for identical input
