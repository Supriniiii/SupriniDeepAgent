# Purpose

This test validates that access control mechanisms correctly enforce permissions, verifying that authenticated users can only access resources and operations they are explicitly authorized for. It ensures role-based, attribute-based, or policy-based access control rules are applied consistently, and that privilege escalation vulnerabilities do not exist.

---

# Scope

Covers: Role-based access control (RBAC) enforcement, attribute-based access control (ABAC) evaluation, resource-level permission checks, operation-level permission checks, cross-tenant data isolation, privilege escalation prevention, permission inheritance and delegation, and access denied response consistency.

Excludes: Authentication (identity verification), transport security, application-level business logic beyond access decisions, and infrastructure network segmentation.

---

# Test Objectives

- Verify that each role can access only its explicitly permitted resources and operations
- Confirm that cross-role access attempts are rejected with consistent 403 responses
- Validate that privilege escalation through parameter manipulation is blocked
- Ensure cross-tenant data access is impossible regardless of role within another tenant
- Verify permission inheritance follows documented hierarchy without unintended grants
- Confirm that newly created resources inherit correct default permissions

# Test Procedure

```text
1. Authenticate as each defined role and attempt access to all protected resources
2. Verify permitted operations succeed for each role's authorized resources
3. Verify denied operations return 403 without leaking resource existence
4. Attempt horizontal privilege escalation (access peer user's resources)
5. Attempt vertical privilege escalation (perform admin operations as regular user)
6. Manipulate resource IDs in requests to attempt unauthorized cross-resource access
7. Test cross-tenant access by authenticating as tenant A and requesting tenant B data
8. Verify permission inheritance by creating nested resources and checking access
9. Test permission revocation takes immediate effect on subsequent requests
10. Verify audit log captures all access denied events with sufficient context
```

# Validation Rules

- Every protected resource must reject unauthorized access with HTTP 403 response
- Privilege escalation attempts must be blocked and logged as security events
- Cross-tenant requests must return 403 without confirming resource existence
- Permission changes must take effect within one request cycle (no stale cache)
- Access denied responses must not include resource data or metadata in the body
