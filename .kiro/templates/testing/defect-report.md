# Purpose

This report catalogs and classifies all defects discovered during testing, providing defect severity distribution, affected component mapping, root cause categorization, resolution status tracking, and trend analysis. It serves as the authoritative record of known issues and supports prioritization of remediation efforts.

---

# Scope

Covers: Defect inventory with unique identifiers, severity classification (critical/high/medium/low), affected component mapping, root cause categorization, reproduction steps documentation, resolution status tracking, defect aging analysis, defect density per component, and trend comparison with previous test cycles.

Excludes: Feature requests, enhancement suggestions, technical debt items not manifesting as defects, and defects found in earlier releases already documented elsewhere.

---

# Test Objectives

- Catalog every defect with unique identifier, severity, and affected component
- Classify defects by root cause category for systemic issue identification
- Track resolution status from discovery through verification of fix
- Calculate defect density per component to identify quality hotspots
- Analyze defect aging to identify stale unresolved issues
- Compare defect trends against previous cycles to assess quality trajectory

# Test Procedure

```text
1. Collect all defects from test execution results across all test categories
2. Assign unique identifiers and classify severity (critical/high/medium/low)
3. Map each defect to the affected component and subsystem
4. Categorize root cause (logic error, integration issue, configuration, data)
5. Document reproduction steps sufficient for developer investigation
6. Track resolution status (open, in progress, fixed, verified, closed)
7. Calculate defect density (defects per KLOC or per component)
8. Analyze defect age distribution to identify stale issues
9. Compare current defect counts against previous test cycle for trends
10. Generate report with severity breakdown, component heatmap, and trend charts
```
